# Product Requirements Document (PRD)
## Trading Core System

## 1. 개요

Trading Core System은 AI 기반 자동화 암호화폐 트레이딩 플랫폼으로, 바이낸스 API를 활용하여 실시간 데이터 수집, 분석, 자동 매매를 수행합니다.

### 1.1 목적
- 실시간 암호화폐 시장 데이터 수집 및 분석
- AI 기반 매매 의사결정 지원
- 자동화된 포지션 진입/청산 실행
- 사용자 대시보드를 통한 투명한 트레이딩 모니터링

### 1.2 주요 기능
- 실시간 시장 데이터 수집 (차트, 뉴스, 시장 지표)
- AI 기반 매매 신호 생성
- 자동화된 매매 실행
- 사용자 대시보드 제공
- AI 챗봇을 통한 질의응답

---

## 2. 시스템 아키텍처

### 2.1 모듈 구성

#### 2.1.1 데이터 수집 모듈 (Data Collection Module)
**역할**: 외부 소스로부터 원천 데이터를 수집하는 모듈

**주요 기능**:
- 바이낸스 API를 통한 실시간 코인 차트 정보 수집
  - 캔들스틱 데이터 (OHLCV)
  - 거래량 데이터
  - 호가창 데이터
  - 실시간 가격 틱 데이터
- 코인에 영향을 줄 수 있는 외부 요소 수집
  - 뉴스 기사 수집 (크립토 뉴스 사이트, RSS 피드)
  - 소셜 미디어 감정 분석 데이터 (트위터, 레딧 등)
  - 온체인 데이터 (체인 분석, 거래소 유입/유출)
  - 거시경제 지표 (비트코인 도미넌스, 공포탐욕 지수 등)
- 데이터 수집 스케줄링 및 재시도 로직
- 데이터 검증 및 품질 관리

**책임 범위**:
- 원천 데이터의 수집에만 집중
- 데이터 가공은 하지 않음
- 수집된 데이터를 저장소에 저장

#### 2.1.2 데이터 가공 모듈 (Data Processing Module)
**역할**: 수집된 원천 데이터를 다양한 용도에 맞게 가공하는 모듈

**주요 기능**:
- AI 판단용 데이터 가공
  - 기술적 지표 계산 (RSI, MACD, 볼린저 밴드, 이동평균 등)
  - 시계열 데이터 정규화 및 전처리
  - 뉴스 및 감정 데이터 벡터화
  - AI 모델 입력 형식으로 변환
- 대시보드용 데이터 가공
  - 실시간 차트 데이터 집계
  - 통계 지표 계산 (수익률, 승률, 최대 낙폭 등)
  - 사용자 친화적 형식으로 변환
  - 캐싱 및 최적화
- 데이터 변환 파이프라인 관리
- 데이터 일관성 보장

**책임 범위**:
- 원천 데이터를 목적에 맞게 변환
- 여러 소비자(AI, 대시보드)를 위한 데이터 형식 제공

#### 2.1.3 코인 매매 모듈 (Trading Module)
**역할**: 실제 코인 매매 로직을 처리하는 모듈

**주요 기능**:
- 바이낸스 API를 통한 포지션 관리
  - Long 포지션 진입/청산
  - Short 포지션 진입/청산
  - 레버리지 설정
  - 주문 유형 관리 (시장가, 지정가, 스탑로스 등)
- 주문 실행 및 상태 추적
  - 바이낸스 API 호출
  - 주문 상태 모니터링
  - 재시도 로직 (Exponential Backoff)
  - 서킷 브레이커 (Resilience4j)
- 거래 이력 기록
- 리스크 관리 모듈과의 연동

**책임 범위**:
- 실제 매매 실행
- 포지션 관리
- 외부 API 호출 및 에러 처리
- 리스크 검증 요청 (리스크 관리 모듈에 위임)

#### 2.1.3-1 리스크 관리 모듈 (Risk Management Module) ⭐ 신규
**역할**: 매매 전 리스크를 검증하고 관리하는 독립 모듈

**주요 기능**:
- 리스크 검증
  - 포지션 크기 계산 (잔고, 리스크 파라미터 기반)
  - 손절/익절가 계산 (변동성, 리스크/보상 비율 기반)
  - 손실 한도 검사 (일일/전체 손실 한도)
  - 최대 포지션 수 제한
- 리스크 정책 관리
  - 리스크 파라미터 설정
  - 정책 변경 및 버전 관리
- 감사 로그
  - 모든 리스크 검증 결과 기록
  - 승인/거부 사유 기록

**책임 범위**:
- 리스크 검증 로직의 독립적 관리
- 여러 매매 전략에서 재사용 가능한 리스크 모듈 제공
- 리스크 정책의 중앙 관리

#### 2.1.4 AI 모듈 (AI Module)
**역할**: AI 기반 의사결정 및 질의응답을 제공하는 모듈

**주요 기능**:
- 포지션 진입 판단
  - 가공된 데이터를 기반으로 AI 모델에 질의
  - 매수/매도/보류 신호 생성
  - 신뢰도 점수 제공
  - 판단 근거 설명 생성
- 사용자 챗봇 기능
  - 코인에 대한 질의응답
  - 시장 분석 요청 처리
  - 전략 설명 및 조언 제공
  - 자연어 처리 및 대화 관리
- AI 모델 관리
  - 모델 로딩 및 캐싱
  - 모델 버전 관리
  - 성능 모니터링

**책임 범위**:
- AI 기반 의사결정 지원
- 자연어 기반 상호작용 제공

#### 2.1.5 API Logic 모듈 (API Module)
**역할**: 프론트엔드에 RESTful API를 제공하는 모듈

**주요 기능**:
- 사용자 인증 및 권한 관리
- 대시보드 데이터 API
  - 실시간 차트 데이터 조회
  - 포지션 현황 조회
  - 수익률 통계 조회
  - 거래 이력 조회
- AI 챗봇 API
  - 채팅 메시지 전송/수신
  - 대화 히스토리 관리
- 설정 관리 API
  - 트레이딩 전략 설정
  - 리스크 파라미터 설정
  - 알림 설정
- API 문서화 (Swagger/OpenAPI)
- 요청/응답 검증 및 에러 처리

**책임 범위**:
- 외부 인터페이스 제공
- 비즈니스 로직과의 연결

## 3. Use Cases

### 3.1 자동 매매 실행 (Automated Trading Execution)

**액터**: 시스템 (자동화된 프로세스)

**전제 조건**:
- 트레이딩 전략이 활성화되어 있음
- 바이낸스 API 연결이 정상
- 충분한 잔고가 있음

**기본 흐름**:
1. 데이터 수집 모듈이 실시간 시장 데이터를 수집 (재시도 로직 포함)
2. 데이터 가공 모듈이 수집된 데이터를 AI 판단용 형식으로 가공
3. 코인 매매 모듈이 AI 모듈에 포지션 진입 여부를 질의
4. AI 모듈이 가공된 데이터를 분석하여 매수/매도/보류 신호를 반환
5. 코인 매매 모듈이 신호가 "매수" 또는 "매도"인 경우:
   - 리스크 관리 모듈에 리스크 검증 요청
   - 리스크 관리 모듈이 포지션 크기, 손절/익절가 계산 및 검증 수행
   - 리스크 검증 통과 시 바이낸스 API를 통해 주문 실행 (서킷 브레이커, 재시도 로직 포함)
   - 리스크 검증 실패 시 주문 거부 및 감사 로그 기록
   - 주문 결과를 데이터베이스에 기록
6. API Logic 모듈이 대시보드에 실시간 업데이트 전송

**대안 흐름**:
- 1a. 데이터 수집 실패 시 Exponential Backoff로 재시도 (최대 3회)
- 3a. AI 모듈이 "보류" 신호를 반환하면, 다음 주기까지 대기
- 5a. 리스크 관리 모듈에서 최대 손실 한도를 초과하면 주문 거부 및 감사 로그 기록
- 5b. 바이낸스 API 호출 실패 시 재시도 로직 실행 (Exponential Backoff)
- 5c. 바이낸스 API 장애 시 서킷 브레이커가 열려 자동 차단

**사후 조건**:
- 주문이 성공적으로 실행되거나 실패 사유가 기록됨
- 포지션 상태가 업데이트됨

---

### 3.2 포지션 청산 (Position Liquidation)

**액터**: 시스템 (자동화된 프로세스 또는 사용자)

**전제 조건**:
- 활성 포지션이 존재함
- 청산 조건이 충족됨 (익절/손절/시간 기반)

**기본 흐름**:
1. 코인 매매 모듈이 활성 포지션을 모니터링
2. 현재 가격이 청산 조건(익절가/손절가)에 도달하거나 시간 기반 청산 조건 충족
3. 코인 매매 모듈이 바이낸스 API를 통해 청산 주문 실행
4. 청산 결과를 데이터베이스에 기록
5. 수익/손실 계산 및 통계 업데이트
6. 대시보드에 청산 알림 전송

**대안 흐름**:
- 3a. 청산 주문 실패 시 Exponential Backoff로 재시도 (최대 3회)
- 3b. 서킷 브레이커가 열려 있으면 주문 실행 중단 및 알림
- 2a. 급격한 가격 변동으로 슬리피지 발생 시 부분 청산 고려

---

### 3.3 실시간 대시보드 조회 (Real-time Dashboard View)

**액터**: 사용자

**전제 조건**:
- 사용자가 로그인되어 있음
- 대시보드 페이지에 접속

**기본 흐름**:
1. 사용자가 대시보드 페이지 접속
2. API Logic 모듈이 사용자 인증 확인
3. API Logic 모듈이 데이터 가공 모듈에 대시보드용 데이터 요청
4. 데이터 가공 모듈이 최신 데이터를 가공하여 반환
5. API Logic 모듈이 가공된 데이터를 프론트엔드에 전송
6. 사용자가 실시간 차트, 포지션 현황, 수익률 등을 확인
7. WebSocket 또는 Server-Sent Events를 통해 실시간 업데이트 수신

**대안 흐름**:
- 3a. 캐시된 데이터가 있으면 Redis 캐시에서 반환
- 4a. 데이터 가공 실패 시 에러 메시지 반환 및 로깅
- 4b. 시계열 데이터 조회 시 TimescaleDB 활용

---

### 3.4 AI 챗봇 질의응답 (AI Chatbot Query)

**액터**: 사용자

**전제 조건**:
- 사용자가 로그인되어 있음
- 챗봇 인터페이스에 접속

**기본 흐름**:
1. 사용자가 챗봇에 질문 입력 (예: "비트코인 현재 추세는?")
2. API Logic 모듈이 질문을 수신
3. API Logic 모듈이 AI 모듈에 질문 전달
4. AI 모듈이 필요한 데이터를 데이터 가공 모듈에서 조회
5. AI 모듈이 데이터를 분석하여 답변 생성
6. AI 모듈이 자연어 답변을 반환
7. API Logic 모듈이 답변을 사용자에게 전송
8. 대화 히스토리가 저장됨

**대안 흐름**:
- 4a. 질문이 특정 코인에 대한 것이면 해당 코인 데이터만 조회
- 5a. AI 모델 응답 실패 시 기본 답변 또는 에러 메시지 반환

---

### 3.5 데이터 수집 스케줄링 (Data Collection Scheduling)

**액터**: 시스템 (스케줄러)

**전제 조건**:
- 스케줄러가 활성화되어 있음
- 외부 API 연결이 정상

**기본 흐름**:
1. 스케줄러가 설정된 주기(예: 1분마다)로 데이터 수집 작업 트리거
2. 데이터 수집 모듈이 바이낸스 API에서 최신 차트 데이터 수집
3. 데이터 수집 모듈이 뉴스 피드, 소셜 미디어 등에서 최신 정보 수집
4. 수집된 데이터를 검증
5. 검증된 데이터를 데이터베이스에 저장
6. 데이터 가공 모듈에 새 데이터 알림 전송

**대안 흐름**:
- 2a. API 호출 실패 시 Exponential Backoff로 재시도 (최대 3회)
- 2b. 서킷 브레이커가 열려 있으면 데이터 수집 중단 및 알림
- 4a. 데이터 검증 실패 시 구조화된 로그 기록 후 다음 주기로 건너뜀
- 5a. 원천 데이터는 PostgreSQL에, 시계열 데이터는 TimescaleDB에 저장

---

### 3.6 트레이딩 전략 설정 (Trading Strategy Configuration)

**액터**: 사용자

**전제 조건**:
- 사용자가 로그인되어 있음
- 관리자 권한 또는 설정 권한이 있음

**기본 흐름**:
1. 사용자가 설정 페이지에서 트레이딩 전략 파라미터 입력
   - 진입 조건 (예: RSI < 30)
   - 청산 조건 (익절가, 손절가)
   - 포지션 크기
   - 리스크 한도
2. API Logic 모듈이 입력값 검증
3. 검증된 설정을 데이터베이스에 저장
4. 코인 매매 모듈에 설정 변경 알림
5. 코인 매매 모듈이 새 설정을 적용
6. 설정 변경 확인 메시지 반환

**대안 흐름**:
- 2a. 검증 실패 시 에러 메시지와 함께 저장 거부
- 4a. 활성 포지션이 있는 경우 설정 변경 제한 또는 경고

---

### 3.7 수익률 리포트 생성 (Profitability Report Generation)

**액터**: 사용자 또는 시스템 (스케줄러)

**전제 조건**:
- 거래 이력이 존재함

**기본 흐름**:
1. 사용자가 리포트 페이지 접속 또는 스케줄러가 주기적으로 리포트 생성
2. API Logic 모듈이 리포트 요청 수신
3. 데이터 가공 모듈이 거래 이력을 집계하여 통계 계산
   - 총 수익률
   - 승률
   - 평균 수익/손실
   - 최대 낙폭 (Max Drawdown)
   - 샤프 비율
4. 데이터 가공 모듈이 리포트 데이터 생성
5. API Logic 모듈이 리포트를 사용자에게 전송 또는 이메일 발송

---

## 4. 비기능 요구사항

### 4.1 성능
- 데이터 수집: 1분 이내 최신 데이터 수집 완료
- AI 판단: 5초 이내 포지션 진입 판단 완료
- API 응답: 평균 200ms 이내 응답
- 대시보드 실시간 업데이트: 1초 이내 지연

### 4.2 안정성
- 시스템 가동률: 99.9% 이상
- 데이터 손실 방지: 모든 거래 이력 영구 저장
- 장애 복구: 자동 재시도 및 알림 시스템
- 재시도 전략: Exponential Backoff (1초, 2초, 4초, 8초...)
- 서킷 브레이커: Resilience4j를 통한 외부 API 장애 시 자동 차단
- 데드 레터 큐: 실패한 작업 저장 및 재처리 가능

### 4.3 보안
- API 키 관리: HashiCorp Vault 또는 환경 변수를 통한 안전한 저장
- 데이터 암호화: 
  - 저장 시 암호화 (encryption at rest)
  - 전송 시 암호화 (TLS)
- 사용자 인증 및 권한 관리: Spring Security 기반
- API 요청 제한 (Rate Limiting)
- 민감 정보 마스킹: 로그에서 자동 마스킹
- 감사 로그: 모든 중요한 작업 기록 (매매 실행, 설정 변경, 리스크 검증)

### 4.4 확장성
- 모듈별 독립적 확장 가능
- 수평 확장 지원 (로드 밸런싱)
- 데이터베이스 샤딩 지원
- 캐싱 레이어 (Redis)를 통한 성능 최적화
- 시계열 데이터베이스 (TimescaleDB)를 통한 시계열 데이터 최적화

### 4.5 모니터링 및 로깅
- 구조화된 로깅: JSON 형식의 로그 출력
- 로그 레벨: ERROR, WARN, INFO, DEBUG
- 메트릭 수집: Prometheus를 통한 메트릭 수집
- 시각화: Grafana를 통한 대시보드 제공
- 분산 추적: OpenTelemetry를 통한 요청 추적
- 알림: PagerDuty, Slack 등을 통한 장애 알림

### 4.6 설정 관리
- 환경별 설정 분리: local, sandbox, production
- 동적 설정 변경: `/actuator/refresh` 엔드포인트를 통한 재시작 없이 설정 변경
- 설정 중앙화: Spring Cloud Config (선택 사항)
- 민감 정보 암호화: Spring Cloud Config 암호화 기능

## 5. 기술 스택

### 5.1 백엔드
- 언어: Kotlin
- 프레임워크: Spring Boot
- 모듈화: Spring Modulith
- 데이터베이스: 
  - PostgreSQL (원천 데이터: 거래 이력, 설정, 사용자 정보)
  - TimescaleDB (시계열 데이터: 차트 데이터, 가격 틱)
  - Redis (캐시: 대시보드 데이터, 실시간 지표)
- 마이그레이션: Flyway
- 재시도 및 회복력: Resilience4j (서킷 브레이커, 재시도)
- 모니터링: Spring Actuator, Prometheus, Grafana
- 로깅: Logback (구조화된 JSON 로깅)
- 설정 관리: Spring Cloud Config (선택), 환경 변수
- 보안: Spring Security, HashiCorp Vault (선택)

### 5.2 외부 연동
- 바이낸스 API: REST API, WebSocket
- AI 모델: (구현 시 결정)
- 뉴스 수집: RSS, 크롤링, API

### 5.3 인프라
- 컨테이너: Docker
- 오케스트레이션: Docker Compose (개발 환경)
- 모니터링 스택: Prometheus, Grafana
- 로깅 스택: ELK (Elasticsearch, Logstash, Kibana) 또는 Loki
- 분산 추적: OpenTelemetry, Zipkin
